# 养基宝持仓查询性能优化

> 日期：2026-07-03

## 背景

养基宝持仓面板打开时加载慢，主要原因：

1. **`GET /api/yjb/holdings` 每次查库** — 前端每次打开面板都请求此接口，直接走 PostgreSQL 查询，无缓存
2. **`POST /api/yjb/sync` 串行调用外部 API** — 同步接口串行调用 3 次 YJB 外部 API（账户列表 + 账户汇总 + 持仓明细），外网延迟叠加导致响应慢

## 优化方案

### 一、持仓数据 Redis 缓存

**文件**：`YjbServiceImpl.java`

为 `getHoldings` 和 `getAccountSummary` 查询增加 Redis 缓存层：

| 方法 | 缓存 Key | TTL |
|------|----------|-----|
| `getHoldings(userId)` | `cache:yjb:holdings:{userId}` | 30 min |
| `getAccountSummary(userId)` | `cache:yjb:collect:{userId}` | 30 min |

- 查询时优先读缓存，命中直接返回，未命中查 DB 后回写缓存
- `syncHoldings` 落库后自动清除该用户的两个缓存 key，保证下次读取拿到最新数据
- 缓存命名风格与项目已有的 `cache:conv:` 一致

### 二、同步接口并行请求

**文件**：`YjbController.java`

将 `syncHoldings` 方法中 `getAccountCollect` 和 `getFundHoldings` 两个独立的外部 API 调用从串行改为并行：

```
优化前：getUserAccounts → getAccountCollect → getFundHoldings（串行，3 次外网往返）
优化后：getUserAccounts → [getAccountCollect ∥ getFundHoldings]（并行，2 次外网往返）
```

- 使用 `CompletableFuture.supplyAsync` 并发发起请求，`allOf().join()` 等待两者完成
- 异常处理增加 `getCause()` 解包，确保 `CompletionException` 包装不影响 token 过期检测逻辑
- `accountId` 变量改为 effectively final 的 `finalAccountId`，满足 lambda 捕获要求

## 效果

| 场景 | 优化前 | 优化后 |
|------|--------|--------|
| 打开持仓面板（缓存命中） | 查 DB ~100-300ms | Redis 读取 ~5-10ms |
| 同步数据（sync） | 串行 ~2-6s | 并行 ~1-3s |

## 涉及文件

- `src/main/java/com/xiaomo/agent/yjb/service/impl/YjbServiceImpl.java` — Redis 缓存读写 + 同步后失效
- `src/main/java/com/xiaomo/agent/yjb/controller/YjbController.java` — 并行请求 + 异常解包
