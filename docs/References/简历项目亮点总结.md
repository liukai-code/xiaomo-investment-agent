# 金融投资导学 AI Agent "小墨" — 项目亮点总结

> 面向简历准备的项目亮点梳理，聚焦金融领域与 AI Agent 技术深度。

## 基本信息

- **项目名称**：金融投资导学 AI 助手"小墨"
- **技术栈**：Spring Boot 3.5 + Spring AI 1.0 + Vue 3 + TypeScript + PostgreSQL + Redis + Docker
- **核心能力**：AI Agent 对话（同步/SSE 流式）、50+ 金融工具调用、MCP 外部服务集成、多智能体投研工作流

---

## 一、多智能体投研工作流（核心亮点）

设计 5 层 DAG 工作流，模拟真实券商投研决策流程：

### 工作流架构

```
用户输入（如"分析茅台"）
        │
        ▼
┌─────────────────────────────────────────────┐
│  Layer 1: 并行数据采集（4 个专职分析师 Agent）  │
│  ├─ MarketAnalyst    技术面分析               │
│  ├─ FundamentalsAnalyst  基本面分析           │
│  ├─ NewsAnalyst      新闻事件分析             │
│  └─ SocialAnalyst    舆情情绪分析             │
└─────────────────┬───────────────────────────┘
                  │ 4 份独立报告
                  ▼
┌─────────────────────────────────────────────┐
│  Layer 2: 多空辩论                           │
│  ├─ BullResearcher   看多研究员（多轮论证）    │
│  ├─ BearResearcher   看空研究员（多轮反驳）    │
│  └─ ResearchManager  裁决 → 投资计划          │
└─────────────────┬───────────────────────────┘
                  │ 投资计划（买入/卖出/持有 + 目标价 + 仓位）
                  ▼
┌─────────────────────────────────────────────┐
│  Layer 3: 交易员决策                         │
│  └─ Trader → 交易方案（入场价/止损止盈/风险收益比）│
└─────────────────┬───────────────────────────┘
                  │ 交易方案
                  ▼
┌─────────────────────────────────────────────┐
│  Layer 4: 风险评估三方辩论                    │
│  ├─ AggressiveAnalyst  激进分析师             │
│  ├─ ConservativeAnalyst  保守分析师           │
│  ├─ NeutralAnalyst     中立分析师             │
│  └─ RiskJudge          最终裁决               │
└─────────────────┬───────────────────────────┘
                  │ 最终决策（action + confidence + target_price）
                  ▼
┌─────────────────────────────────────────────┐
│  Layer 5: 风险覆盖（可配置硬性风控规则）        │
└─────────────────────────────────────────────┘
```

### 技术实现要点

- 每层 Agent 通过 Spring AI Tool Calling 调用真实金融数据 API，所有分析数据来自工具返回而非模型幻觉
- 工作流引擎基于 Reactor Flux 实现异步编排，支持 SSE 实时推送每层进度
- 辩论机制：多轮对抗式辩论（Bull vs Bear），每轮引用对方论据进行反驳，避免单 Agent 偏见
- 分析结果持久化到 PostgreSQL，支持历史回溯

### 涉及的角色与系统提示词

- 11 个 Agent 角色，每个角色有独立的系统提示词、工具白名单、守卫参数配置
- 输出格式统一为 JSON 结构化（signal/confidence/reasoning），便于下游解析和裁决

## 二、A 股全栈数据中台

移植 44 个金融数据端点为 8 个 Router Tool，覆盖投研全链路。

### 数据能力矩阵

| Tool | 数据维度 | 核心端点 | 数据源 |
|------|---------|---------|--------|
| AStockQuoteRouterTool | 实时行情 + K 线 | tencentQuote（PE/PB/市值/换手率/量比/振幅）、baiduKline（K线+MA5/10/20） | 腾讯/百度 |
| AStockReportRouterTool | 研报 + 估值 | stockReport（机构评级/目标价）、thsEpsForecast（一致预期EPS）、iwencaiSearch（NL语义选股） | 东财/同花顺/iwencai |
| AStockSignalRouterTool | 资金信号 | conceptBlocks（板块归属）、dragonTigerBoard（龙虎榜席位）、lockupExpiry（限售解禁） | 东财 push2/datacenter |
| AStockCapitalRouterTool | 资金面 | marginTrading（融资融券）、holderNumChange（股东户数）、dividendHistory（分红送转）、northboundFlow（北向资金） | 东财 datacenter |
| AStockNewsRouterTool | 新闻公告 | stockNews（个股新闻）、cninfoAnnouncements（巨潮公告全文）、irmQA（互动易问答）、sinaFinancialReport（财报三表） | 东财/巨潮/新浪 |
| AStockLimitUpRouterTool | 打板情绪 | ztPool/zbPool/dtPool（涨停/炸板/跌停池）、sentimentOverview（炸板率/连板梯队）、thsLimitUpPool（涨停揭秘含题材归因） | 东财 push2ex/同花顺 |
| AStockOptionRouterTool | ETF 期权 | optionCodes（期权合约）、optionTQuote（T型报价）、optionGreeks（希腊字母/IV） | 新浪 |
| AStockSentimentRouterTool | 市场舆情 | thsHotList（同花顺热榜）、emHotRank（东财人气榜）、emConceptHit（个股概念命中+热度值） | 同花顺/东财 |

### 防封策略

- 东财接口统一走 `EastMoneyRateLimiter`：串行限流 ≥1s + 随机 200~500ms 抖动
- HTTP 请求伪造浏览器 UA，避免被识别为爬虫
- 腾讯行情优先（不封 IP），东财作为补充数据源

### 44 个端点 → 8 个 Router Tool 的设计思路

- 每个 Router Tool 通过 `operation` 参数路由到具体端点，减少工具数量降低 LLM 选择成本
- 参数校验统一在 Router 层完成，具体端点只负责数据获取和解析
- 返回格式统一为结构化文本（Markdown 表格/列表），LLM 友好

## 三、养基宝基金持仓集成

对接养基宝第三方 API，实现用户真实基金持仓数据与 AI 投研的打通。

### 功能链路

1. **扫码登录**：前端展示养基宝二维码 → 轮询扫码状态 → 获取 Token
2. **多账户管理**：获取用户所有养基宝账户列表，支持切换
3. **持仓明细**：基金代码/名称/持有金额/成本/收益/持有天数/分类
4. **批量估值**：调用养基宝公网 API 批量获取基金实时净值和估算涨幅
5. **AI 个性化建议**：Agent 可直接读取用户真实持仓数据，结合行情工具给出调仓建议

### 技术要点

- 签名机制：`MD5(path + token + timestamp + SECRET)` 请求签名
- 前端独立组件：`YjbQrLogin`（扫码）、`FundHoldings`（持仓）、`AccountSummary`（汇总）、`IndexQuotes`（指数行情）
- Pinia 状态管理：`yangjibaoStore` 管理登录态、账户列表、持仓数据

## 四、工具调用安全守卫系统

金融场景对 Agent 可靠性要求极高，设计了多层防护机制。

### 守卫信号分级

| 级别 | 触发条件 | 行为 |
|------|---------|------|
| NONE | 正常 | 不干预 |
| ADVISORY | 软上限到达 / 相似调用 / 重复 URL | 提示 Agent 评估是否继续 |
| WARNING | 信息增益 LOW / 完全重复调用 / 升级警告 | 强烈建议停止 |
| CRITICAL | 即将到达硬上限 | 必须停止，returnDirect=true |
| FORCE | 硬上限到达 / 抓取次数超限 | 强制停止，returnDirect=true |

### 核心机制

- **信息增益追踪**：`InfoGainTracker` 计算相邻轮次工具返回内容的余弦相似度，连续无新信息时触发告警
- **重复调用检测**：`RepetitionDetector` 检测相同工具+参数组合的重复调用
- **抓取次数限制**：per-role 可配置的 maxFetches（如技术面分析师最多 5 次网页抓取）
- **标的范围守卫**：`GuardInterceptor` 从用户查询中自动解析股票代码，拦截对非目标标的的工具调用
- **注入式信号**：守卫信号以 `[GUARD: level]...[/GUARD]` 格式注入到 Agent 消息流中，引导 Agent 自主决策

### 设计理念

不是硬性截断，而是分级引导——让 Agent 在收到信号后自主决定是否停止，保持 Agent 的自主性同时防止失控。

## 五、工程化亮点

### Per-User API Key 路由

- 支持用户配置自定义 AI 模型（API Key + Base URL + Model Name）
- 工作流中通过 `UserConfigService.getUserChatModel(userId)` 动态切换 ChatModel
- 不同用户可使用不同模型（如 GPT-4 / Claude / 本地模型），系统级无感知

### SSE 流式全链路

- 后端 `Flux<WorkflowEvent>` 累积全文，前端 `ReadableStream` 实时解析渲染
- 工作流进度实时推送：每层开始/完成/Agent 输出均通过 SSE 推送到前端
- 前端 Markdown 流式解析：`useMarkdownBlocks` composable 实现流式友好渲染

### Redis 多级缓存

| 缓存层 | TTL | 用途 |
|--------|-----|------|
| 会话列表 | 30min | 首页会话列表快速加载 |
| 消息列表 | 1h | 历史消息缓存 |
| 最近消息 | 10min | 热数据零 DB 查询 |

### 安全机制

- **Token 认证**：Redis 存储 72h TTL，同设备新登录互踢旧会话
- **对话数据隔离**：所有访问路径统一校验用户归属，防止越权访问
- **密码传输**：客户端 SHA-256 → 服务端 BCrypt 双重加密
- **SQL 白名单**：SqlTool 仅允许 SELECT，禁止 INSERT/UPDATE/DELETE/DROP 等危险关键词

### Docker 部署

- 多阶段构建：Node 20（前端编译）→ JDK 17（后端编译）→ JRE 17（运行时）
- `docker-compose up --build` 一键启动：App + PostgreSQL + Redis
