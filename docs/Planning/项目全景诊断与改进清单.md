## 三、工程质量问题

### 3.1 高优先级

#### P0-1: CI/CD 完全缺失

没有任何自动化构建/测试/部署流程。无 GitHub Actions、GitLab CI、Jenkinsfile 等。

**建议方案：**

```yaml
# .github/workflows/ci.yml
name: CI
on: [push, pull_request]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: 17
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: cd frontend && npm ci && npm run build
      - run: mvn clean verify -B
```

#### P0-3: 前端零测试

- 没有 Vitest/Jest 配置，没有一个测试文件
- SSE 流式解析、Markdown 渲染、Pinia Store 等核心逻辑未验证
- 建议至少覆盖：`useMarkdownBlocks.ts`、`chat.ts`（SSE 解析）、`stores/auth.ts`

#### P0-4: 数据库迁移不完整

- 仅 2 个迁移文件：`V2__create_user_config_table.sql`、`V3__add_channel_support_to_user_config.sql`
- 缺少 V1（初始表结构迁移），依赖 JPA `ddl-auto: update` 自动建表
- 生产环境风险：`ddl-auto: update` 不会删除列/表，可能导致 schema 不一致

**建议：** 从当前数据库导出 schema，生成 `V1__init_schema.sql`，然后关闭 `ddl-auto: update`

### 3.2 中优先级

#### P1-1: AgentLoopImpl 代码重复

`chat()` 和 `chatStream()` 两个方法中，工具上下文构建（toolCtx）和工具过滤逻辑存在约 100 行重复代码。

**建议：** 提取 `buildToolContext()` 和 `filterTools()` 公共方法。

#### P1-2: 安全加固

| 问题 | 位置 | 建议 |
|------|------|------|
| admin 默认密码 `admin123` | `application.yml` | 生产环境必须通过环境变量覆盖，启动时校验非默认值 |
| 密码逻辑写在 Controller 层 | `AuthController` | 移至 AuthService |
| `@RequestBody Map<String, String>` 缺校验 | `AuthController` | 改为 DTO + `@Valid` |

#### P1-3: 缺少生产配置

没有独立的 `application-prod.yml`，生产/开发共用同一配置文件。

**建议：**
- 创建 `application-prod.yml`，覆盖数据库、Redis、日志级别等配置
- 关闭 `ddl-auto: update`，改用 Flyway 管理
- 关闭 H2 console、SQL 日志等调试功能

#### P1-4: 前端代码规范

缺少 ESLint/Prettier 配置，无法保证代码风格一致性。

**建议：**
```bash
cd frontend
npm install -D eslint @eslint/js eslint-plugin-vue prettier eslint-config-prettier
```

#### P1-5: Spring AI 版本风险

当前使用 `1.1.0-M3`（里程碑版本），非正式 GA 版本，API 可能变动。

**建议：** 关注 Spring AI GA 版本发布，评估升级成本。

## 四、优化建议

### 4.1 性能优化

| 方向 | 说明 |
|------|------|
| Redis 缓存监控 | 当前有缓存但无可观测性，建议加 metrics 统计命中率 |

### 4.2 架构优化

| 方向 | 说明 |
|------|------|
| AgentLoopImpl 拆分 | 785 行上帝类，建议拆为 ToolExecutor、ContextBuilder、StreamHandler 等 |
| 工具注册机制 | 当前通过 `@Component` + 手动注册，可考虑注解扫描自动发现 |
| Workflow 节点解耦 | 各节点（AnalystNode、DebateNode 等）可抽象为统一接口，支持配置化编排 |
