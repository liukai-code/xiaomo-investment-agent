## P1 — 短期改进（影响可维护性）

### 1. 重构为按功能模块分包

**现状：** 所有业务代码在 `agent/` 包下按技术层（controller/service/repository/entity）组织。

**目标：** 改为按功能模块分包（Package by Feature），模块边界清晰，便于定位代码和控制耦合。

```
com.itlk.myclaudecode/
├── MyClaudeCodeApplication.java
├── common/                        # 通用基础设施
│   ├── entity/                    # Result 等通用类
│   ├── exception/                 # 全局异常处理（GlobalExceptionHandler）
│   └── config/                    # RedisConfig, WebMvcConfig
├── auth/                          # 认证模块
│   ├── controller/AuthController.java
│   ├── service/TokenManager.java
│   ├── service/impl/TokenManagerImpl.java
│   └── interceptor/AuthInterceptor.java
├── user/                          # 用户模块
│   ├── entity/User.java
│   ├── repository/UserRepository.java
│   └── service/UserService.java
├── conversation/                  # 对话模块
│   ├── entity/Conversation.java
│   ├── entity/ChatMessage.java
│   ├── entity/MessageRole.java
│   ├── controller/AgentLoopController.java
│   ├── repository/ConversationRepository.java
│   ├── repository/ChatMessageRepository.java
│   ├── service/ConversationService.java
│   ├── service/ChatMessageService.java
│   └── service/ChatHistoryCacheService.java
├── agent/                         # Agent 核心
│   ├── service/AgentLoop.java
│   └── service/impl/AgentLoopImpl.java
└── tool/                          # Agent 工具
    ├── config/ToolConfig.java
    ├── FileListTool.java
    ├── FileReadTool.java
    ├── FileWriteTool.java
    ├── FinancialDataTool.java
    └── SqlTool.java
```

**操作步骤：**
1. 创建新包目录结构
2. 移动文件到对应模块包下
3. 更新所有 package 声明和 import 语句
4. 验证 Spring 组件扫描能正确发现所有 Bean

**注意事项：**
- `@SpringBootApplication` 默认扫描主类所在包及子包，移动文件后需确认扫描范围覆盖所有模块
- 若模块包与主包不在同一层级，需在 `@ComponentScan` 中显式声明

### 2. 补充 Dockerfile + docker-compose.yml

**目标：** 一键启动开发/部署环境，降低环境配置成本。

**需要包含：**
- `Dockerfile`：多阶段构建，第一阶段编译前端 + 后端，第二阶段只打包运行时
- `docker-compose.yml`：编排 PostgreSQL、Redis、应用三个服务
- `.dockerignore`：排除 target/、node_modules/、.git/ 等

**参考结构：**
```yaml
# docker-compose.yml
services:
  app:
    build: .
    ports: ["4545:4545"]
    environment:
      - DB_HOST=postgres
      - REDIS_HOST=redis
      - ANTHROPIC_API_KEY=${ANTHROPIC_API_KEY}
    depends_on: [postgres, redis]
  postgres:
    image: postgres:16
    environment:
      POSTGRES_DB: myclaudecode
      POSTGRES_USER: ${DB_USER}
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes: [pgdata:/var/lib/postgresql/data]
  redis:
    image: redis:7-alpine
volumes:
  pgdata:
```

## P2 — 中期改进（影响质量保障）

### 4. 补充后端单元测试

**现状：** 仅 1 个 Spring Boot context load test，核心业务逻辑无测试覆盖。

**优先测试目标：**

| 优先级 | 类 | 测试重点 |
|--------|-----|---------|
| 高 | `AgentLoopImpl` | chat()、chatStream()、generateTitle() 的核心逻辑 |
| 高 | `ChatMessageServiceImpl` | saveMessage()、getHistory()、saveAssistantMessage() |
| 高 | `ConversationServiceImpl` | createConversation()、listConversations()、checkOwnership() |
| 中 | `TokenManagerImpl` | JWT 生成/验证、BCrypt 加密 |
| 中 | `ChatHistoryCacheServiceImpl` | Redis 缓存读写、过期、失效 |
| 低 | `SqlTool` | SQL 注入防护、只读校验 |
| 低 | `FinancialDataTool` | 外部 API 调用 Mock |

**测试框架：** 已有 `spring-boot-starter-test`，可直接使用 JUnit 5 + Mockito + `@SpringBootTest`。

**建议：** 为 Service 层编写单元测试（Mock Repository），为 Controller 层编写 `@WebMvcTest` 切片测试。

### 5. 添加 CI Pipeline

**目标：** 每次 push/PR 自动执行构建和测试，防止回归。

**推荐方案：** GitHub Actions（项目已在 Git 管理下）。

```yaml
# .github/workflows/ci.yml
name: CI
on: [push, pull_request]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: 17
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: cd frontend && npm ci && npm run build
      - run: mvn clean verify -B
```

### 9. 统一构建/启动脚本

**目标：** 一条命令完成常见操作，降低记忆成本。

**方案：** 在项目根目录添加 `Makefile`：

```makefile
.PHONY: dev build test clean

dev:
	cd frontend && npm run dev &
	mvn spring-boot:run

build:
	cd frontend && npm run build
	mvn clean package -DskipTests

test:
	cd frontend && npx vitest run
	mvn test

clean:
	mvn clean
	rm -rf frontend/node_modules frontend/dist target/
```
